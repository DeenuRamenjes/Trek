# Phase 2 (Data) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Drizzle schema for every table in CLAUDE.md §3, versioned migrations that run before the splash is released, repositories, shared zod row schemas, and a deterministic dev seed.

**Architecture:**
- `src/db/schema.ts`: Drizzle `sqliteTable` definitions. `src/db/migrations/`: SQL files generated by `drizzle-kit generate`, bundled through `babel-plugin-inline-import` (`.sql`) and the generated `migrations.js`.
- `src/db/client.ts`: opens `trek.db` with `expo-sqlite` (`enableChangeListener: true`), `PRAGMA foreign_keys = ON`, returns the Drizzle db. `src/db/useMigrations.ts` wraps `drizzle-orm/expo-sqlite/migrator`'s `useMigrations` as a `Readiness` source for `useAppReady`.
- Repositories take a `TrekDb` (Drizzle `BaseSQLiteDatabase<'sync' | 'async', unknown, typeof schema>`) parameter so jest can pass a test db.
- Tests: `src/test/testDb.ts` builds a Drizzle db with `drizzle-orm/sqlite-proxy` over Node's built-in `node:sqlite` `DatabaseSync` (no new dependency) and applies the generated SQL migrations in order.

**Tech Stack:** expo-sqlite, drizzle-orm, drizzle-kit (dev), babel-plugin-inline-import (dev), expo-crypto, zod 4. All are approved in CLAUDE.md §1.

## Global Constraints

- Approved dependencies only. Install with `EXPO_OFFLINE=1 npx expo install expo-sqlite expo-crypto drizzle-orm` and `npm i -D drizzle-kit babel-plugin-inline-import`, then a clean install (`rm -rf node_modules && npm install`).
- Ids are UUID v4 strings from `expo-crypto` `randomUUID()`, except `pending_actions.id` (deterministic key, supplied by the caller).
- Timestamps are ISO strings (`new Date().toISOString()`); dates are `YYYY-MM-DD` text; times are `HH:mm` text.
- Column names in the database are snake_case; Drizzle field names are camelCase and match §3 exactly.
- Enums: trackingType `check|count|duration|value`; scheduleType `daily|weekdays|weekends|customDays|everyNDays|timesPerWeek`; log status `done|partial|skipped` (never `missed`); vacation scope `all|selected`; pending source `notification|widget`; pending action `done|increment|skip|snooze`.
- `logs.note` max 1000 characters (zod). Logs are unique per (goalId, date, slotId) with null slotId counted as one value: unique index on `(goal_id, date, coalesce(slot_id, ''))`.
- `scheduleDays` is a 7-bit mask, bit 0 = Sunday … bit 6 = Saturday.
- Foreign keys cascade on delete from goals to schedule versions, slots (via version), reminders, group_goals, goal_pauses, logs, vacation_goals; from groups to group_goals; from vacations to vacation_goals.
- Schedule versions are never updated: the repository exposes insert only.
- No React or Expo imports in `src/db/rows.ts` (zod row schemas, shared with Phase 11 import).
- jest: `*.test.ts` run in the node project. RNTL 14 is async.
- Verification for every task: `npx tsc --noEmit` and `npx jest`. Phase ends with `EXPO_OFFLINE=1 CI=1 npx expo export --platform ios` and `--platform android` (output to `dist`, then delete `dist`).

### Task 2: Client, migrations at startup, repositories

**Files:** `src/db/client.ts`, `src/db/useMigrations.ts`, `src/db/ids.ts`, `src/db/repositories/{goals,schedules,reminders,groups,pauses,logs,vacations,pendingActions}.ts`, `src/db/repositories/index.ts`, tests in `src/db/repositories/__tests__/`, `src/features/startup/useAppReady.ts` (+ its test).

- [ ] `ids.ts`: `newId()` → `Crypto.randomUUID()`; `nowIso()`. In jest the node project mocks `expo-crypto` via `jest.setup.js` with `require('node:crypto').randomUUID`.
- [ ] `client.ts`: lazy singleton `getDb()` opening `trek.db` (`openDatabaseSync('trek.db', { enableChangeListener: true })`, `PRAGMA foreign_keys = ON; PRAGMA journal_mode = WAL;`), `drizzle(expoDb, { schema })`. Export `type TrekDb`.
- [ ] `useMigrations.ts`: `useDbMigrations(): Readiness` using `useMigrations(getDb(), migrations)`; error is surfaced. Add it to `useAppReady` sources. Update the `useAppReady` test with a mocked `src/db/useMigrations`.
- [ ] Repositories (functions taking `db: TrekDb` first; return plain rows; all mutations set `updatedAt`):
  - goals: `createGoal(db, input)` (only `name` required; inserts the goal plus an initial schedule version `daily`, mask 127, effectiveFrom = startDate, startDate defaulting to the passed `today`), `updateGoal`, `getGoal`, `listGoals({ includeArchived })` ordered by sortOrder, `archiveGoal`, `reorderGoals(ids)`, `duplicateGoal(id, today)` (copies goal, current schedule version, slots and reminders with new ids), `deleteGoal`.
  - schedules: `addScheduleVersion(db, goalId, effectiveFrom, version, slots)` (insert only; if a version with the same effectiveFrom exists, replace that one version and its slots, since it is not yet in the past), `listScheduleVersions(goalId)` ascending, `listSlots(versionId)`.
  - pauses: `pauseGoal(goalId, date)` sets `pausedAt` and opens a pause row; `resumeGoal(goalId, date)` closes the open row with endDate = date − 1 day (or deletes it if that is before startDate) and clears `pausedAt`; `listPauses(goalId)`.
  - reminders: `setReminders(goalId, reminders[])` (replace set), `listReminders(goalId?)`.
  - groups: CRUD, `reorderGroups`, `setGroupGoals(groupId, goalIds)`, `listGroupGoals`.
  - logs: `upsertLog(db, { goalId, date, slotId?, value, status, note? })` (insert or update on the unique key; keeps `loggedAt` from the first insert), `deleteLog`, `listLogs({ goalId?, from?, to? })`.
  - vacations: `createVacation({ startDate, endDate, scope, goalIds?, note? })`, `updateVacation`, `endVacationNow(id, today)` (endDate = today − 1 day; deletes it if it had not started), `deleteVacation`, `listVacations()` with goalIds.
  - pendingActions: `enqueueAction(row)` with `onConflictDoNothing` on id, `listUnprocessed()` ordered by createdAt, `markProcessed(id, at)`.
  - Multi-row writes use `db.transaction`.
- [ ] Repository tests against `createTestDb()` for each function, including: name-only goal gets every default and one version; duplicate copies schedule, slots and reminders; upsert on (goal, date, null slot) updates instead of duplicating; enqueue of the same id twice keeps one row; resume closes the pause; endVacationNow before start deletes.
